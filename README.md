# NetMon

Локальный монитор сетевых обращений приложений для Windows 11 x64. Rust, ETW, egui и SQLite.

## Запуск

Готовая сборка: `artifacts/NetMon/NetMon.exe`. При запуске Windows запросит права администратора.
Установка службы, драйвера и изменения сетевых настроек не нужны.

1. В разделе **Приложения** раскройте список и отметьте одно или несколько имён EXE. Поиск работает без учёта регистра. Например, выбор `game.exe` охватывает все его запущенные копии и экземпляры, которые появятся во время записи, из любой папки.
2. Если игра ещё не запущена, введите её полное имя с расширением и нажмите **Добавить**. В этом же поле можно добавить полный путь для наблюдения за конкретным файлом или `*` для наблюдения за всеми процессами.
3. Опция **Включать дочерние процессы** добавляет потомков с другими именами. Например, при выборе `launcher.exe` в запись попадёт запущенный им `game.exe` и его сетевой помощник. При первом запуске опция включена. Выбор приложений и настройку потомков можно сохранить как группу.
4. Нажмите **Начать запись**, затем выполните действия в игре или лаунчере.
5. Нажмите **Остановить запись** и дождитесь сохранения. Результат доступен в **Истории**.

Рекомендуется начинать запись до запуска отслеживаемого приложения. Для защищённых или очень короткоживущих процессов полный путь может быть недоступен; в таких случаях используйте имя EXE.

## Представления

- **Серверы** — адреса/порты, приложения, возможные домены, количество сессий и суммарный трафик. Адрес открывает связанные соединения.
- **Соединения** — отдельные TCP-соединения и UDP-потоки; нажатие на строку открывает подробности, точные счётчики и источник данных.
- **DNS** — имя, тип запроса, результат Windows DNS Client, ответ и длительность, если запрос удалось однозначно сопоставить с завершением.
- **История** — сохранённые записи. Просмотр истории возможен одновременно с новой записью.

**Экспорт записи** сохраняет всю выбранную запись в JSON и два CSV в `data/exports/` рядом с EXE. Поисковый фильтр интерфейса на экспорт не влияет. Время в JSON/CSV — Unix UTC в миллисекундах; интерфейс отображает местное время Windows.

## Семантика и ограничения первой версии

- TCP: результат подключения и завершение хранятся раздельно. Успешный TCP не доказывает успешный TLS/HTTP или работоспособность приложения.
- Отказы: фиксируются наблюдаемые ошибки Winsock-AFD с оригинальным NTSTATUS. Полное покрытие всех причин отказа на каждой сборке Windows не гарантируется. Отсутствие события не превращается в «успех» или «ошибку».
- UDP: нет установления соединения. Поток группируется по экземпляру процесса, локальному и удалённому адресам/портам, затем закрывается по периоду бездействия (по умолчанию 30 секунд). «Только отправка» не означает отказ.
- Байты: сумма размеров наблюдавшихся событий передачи транспортного стека. Повторы TCP считаются отдельно. Это не размер скачанного файла и не физические байты Ethernet. При наблюдении обеих сторон loopback каждая сторона учитывается в своём потоке; сводный объём включает обе стороны.
- Запись началась позднее соединения либо остановилась до закрытия: данные помечаются как неполные. Уже существующие бездействующие сокеты не перечисляются автоматически.
- Потери ETW, переполнение внутренней очереди и ошибки разбора отражаются в записи. Нулевые потери означают отсутствие известных потерь сборщика, а не гарантию полноты провайдеров Windows.
- DNS: сохраняются результаты системного резолвера, включая его внутренние/повторные попытки. Ошибка одной попытки может сопровождаться успешной следующей. Это не полная копия DNS-пакета: TTL, секции Authority/Additional и точный DNS-сервер не сохраняются.
- Собственный DNS/DoH приложения, обходящий Windows DNS Client, может быть не виден. Содержимое шифрованного DNS не расшифровывается. Записи Pi-hole не импортируются.
- Домен рядом с сервером — предположение по успешному DNS-ответу того же экземпляра процесса за предыдущие 5 минут. Это временное окно, а не DNS TTL. Несколько доменов одного IP сохраняются как несколько кандидатов. Автоматические обратные DNS-запросы не выполняются.
- EXE/PID привязываются к экземпляру процесса по времени запуска. Если приложение делегирует сетевую работу отдельной службе, добавьте EXE службы в группу; родительское дерево не всегда устанавливает такую связь.
- У первой версии лимит 50 000 строк соединений и DNS на запись; при достижении запись останавливается с сообщением. История не удаляется автоматически. Обычная задержка отображения — около 2–3 секунд.

База `data/netmon.sqlite3`, настройки `data/settings.json`. Данные остаются локально. Для другого расположения можно задать переменную `NETMON_DATA_DIR` перед запуском. Аварийно прерванная запись определяется по отсутствию времени окончания; последние ещё не сохранённые события могут быть потеряны.

## Сборка

Нужны Windows 11 x64, Rust MSVC, Visual Studio C++ Build Tools и Windows SDK.
В текущей рабочей папке Rust установлен изолированно в `.tools/`.

```powershell
.\scripts\cargo.ps1 build --locked --offline
.\scripts\cargo.ps1 test --locked --offline
.\scripts\cargo.ps1 fmt --all --check
.\scripts\cargo.ps1 -CargoArgs @('clippy','--locked','--offline','--all-targets','--','-D','warnings')
.\scripts\package.ps1
```

При обычной глобальной установке Rust можно использовать стандартный `cargo`. На новой машине сначала нужен `cargo fetch --locked`; `--offline` работает после загрузки зависимостей. `Cargo.lock` фиксирует зависимости. Release-GUI содержит манифест `requireAdministrator`; debug-сборка допускает просмотр истории без повышения прав.

## Проверка реальными событиями

Из терминала администратора, находясь в корне проекта:

```powershell
.\target\debug\netmon-probe.exe --self-test --output artifacts\probe
```

Тест создаёт локальные TCP/UDP-сокеты, передаёт известные объёмы данных, вызывает неудачное TCP-подключение, выполняет системные DNS-запросы для `example.com` и случайного имени `.invalid`, проверяет IPv6 loopback при его доступности. Отслеживаются только процессы `netmon-probe.exe`. Результаты сохраняются в `report.json` и экспортируются; код завершения 0 означает успех проверок.

`scripts/probe-elevated.ps1` — обёртка для уже повышенного процесса, сохраняющая `console.log` и `exit-code.txt`. Самостоятельно права она не повышает.

## Устройство

- `collector.rs`: Windows FFI, ETW-сессии, события процессов, TCP/UDP, DNS Client и Winsock-AFD. Разбираются проверенные сетевые события версии 2; неизвестная версия учитывается как ошибка разбора.
- `engine.rs`: экземпляры процессов, фильтры, корреляция, состояния сессий, счётчики.
- `runtime.rs`: отдельный поток агрегации, ограниченная очередь, упорядочивание ETW по точному времени, периодическая запись изменений.
- `storage.rs`: SQLite WAL, атомарное сохранение изменений, чтение истории, экспорт.
- `ui.rs`: окно, таблицы с виртуализацией строк, поиск и группы EXE.
- `src/bin/probe.rs`: сквозной тест с реальным трафиком.

Сборщик использует собственные ETW-сессии с уникальными именами, завершает только свои сессии и не меняет правила брандмауэра. Он не внедряет код в игры и не перехватывает содержимое TLS.
