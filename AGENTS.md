# NetMon — руководство для агента

NetMon — локальное приложение на Rust для Windows 11 x64. Пользователь запускает запись от имени администратора, выбирает игры, лаунчеры или утилиты по имени EXE и смотрит, с какими серверами они обменивались данными. Интерфейс и сообщения пользователю — на русском.

Текущее состояние, карта исходников и проверенные сценарии собраны в [handoff.md](handoff.md). Инструкция для пользователя находится в [README.md](README.md), результаты испытаний — в [VALIDATION.md](VALIDATION.md).

## Как должен работать выбор приложений

- В списке есть одна строка на имя EXE независимо от регистра, пути и числа процессов. Поиск и флажки позволяют выбрать несколько имён. Выбранное имя остаётся доступным после выхода процесса. Имя ещё не запущенной игры можно добавить вручную.
- Выбор `game.exe` охватывает все одноимённые процессы с начала записи и те, которые появятся позже, включая запуск из другой папки. Для одного конкретного файла пользователь может явно указать полный путь. Отдельный фильтр `*` охватывает все процессы.
- Флажок **«Включать дочерние процессы»** распространяет запись на потомков с другими именами через несколько поколений. В свежих настройках он включён. Существующие настройки и сохранённые группы восстанавливают выбранное пользователем значение.
- Внутри записи экземпляр процесса определяется парой `(pid, started)`. При поиске предка сопоставляй PID родителя с моментом рождения его непосредственного ребёнка. Windows может повторно выдать тот же PID, пока внук старого процесса ещё работает.
- Для списка достаточно имени из Toolhelp. Доступность полного пути, дескриптора процесса и сетевой активности не должна определять, попадёт ли имя в список.

## Правила интерпретации событий

| Данные | Что сохранять при изменении кода |
| --- | --- |
| TCP | Исход попытки, ошибку NTSTATUS и факт закрытия учитывай раздельно. Установленное соединение сохраняет свой исход и после последующей ошибки. Если начало пропущено, показывай это в записи. |
| UDP | Группируй датаграммы по экземпляру процесса и паре конечных точек. Показывай направления обмена и истечение интервала бездействия. Односторонний обмен сам по себе ничего не говорит о результате доставки. |
| Байты | Складывай размеры событий транспортного стека по направлениям. Повторные передачи TCP имеют свой счётчик. При записи обеих сторон loopback у каждой свои счётчики. |
| DNS | Храни имя, тип, результат и код каждой наблюдаемой завершённой операции Windows DNS Client. Длительность заполняй при однозначной паре начала и завершения. Связь домена с IP в сводке показывай как предположение. |
| Качество записи | Сохраняй признаки неполной сессии, потери ETW, переполнение очереди и ошибки декодирования. Поддерживай представление неизвестного результата. |

## Где менять код и как обращаться с данными

- Работа с Windows и ETW сосредоточена в [collector.rs](src/collector.rs). Callback передаёт события через `try_send`. Запись в БД и обновление окна выполняются за его пределами. При остановке закрывай только сессии, открытые данным сборщиком.
- Общая модель находится в [model.rs](src/model.rs), атрибуция и подсчёт — в [engine.rs](src/engine.rs), порядок событий и жизненный цикл записи — в [runtime.rs](src/runtime.rs). Окно использует снимки `Arc<Snapshot>`. Это же представление используется при открытии истории.
- В [storage.rs](src/storage.rs) обновления SQLite фиксируются одной транзакцией. Сбрасывай отметки изменённых потоков и продвигай позицию сохранённых DNS-строк после успешного commit. При изменении модели учитывай старые JSON-объекты в базе, настройки и сохранённые группы.
- Настройки и история пользователя лежат в `data/` рядом с запущенным EXE либо в каталоге из `NETMON_DATA_DIR`. Для экспериментов используй отдельный каталог данных. В `artifacts/NetMon/data/` может находиться рабочая история. Скрипт упаковки обновляет файлы поставки по отдельности.

## Сборка и проверка

В текущем рабочем каталоге [cargo.ps1](scripts/cargo.ps1) использует Rust из `.tools/` и подготавливает окружение MSVC. Команды PowerShell выполняются из корня проекта.

```powershell
.\scripts\cargo.ps1 build --locked --offline
.\scripts\cargo.ps1 fmt --all -- --check
.\scripts\cargo.ps1 -CargoArgs @('clippy','--locked','--offline','--all-targets','--','-D','warnings')
.\scripts\cargo.ps1 test --locked --offline
.\scripts\package.ps1
```

На чистой машине нужны Rust для `x86_64-pc-windows-msvc`, компоненты C++ Visual Studio и Windows SDK. Если Rust установлен глобально, вызывай `cargo` напрямую. Для заполнения пустого кэша выполни `cargo fetch --locked` тем же Cargo, которым затем будешь собирать. Локальные `.tools/`, `target/` и `artifacts/` исключены из Git.

При изменениях декодирования, порядка событий или подсчёта байтов сквозную проверку удобно начинать с [netmon-probe](src/bin/probe.rs). Порядок запуска с правами администратора и контрольные значения приведены в [handoff.md](handoff.md). Для поставки [package.ps1](scripts/package.ps1) создаёт `artifacts/NetMon/NetMon.exe` и `SHA256.txt`. Release-GUI запрашивает повышение прав через манифест в [build.rs](build.rs). Debug-GUI позволяет проверять интерфейс и открывать историю с обычными правами.
